## 算法修改

1. Q1 保持最大安全载荷、精确集合划分 DP 和词典序目标不变。
2. Q2 将 21 架次声明为可配置的 Pareto 目标，在固定架次切片内运行 500000 次确定性变邻域搜索，再追加 100000 次联合资源重排；禁用会改变架次数的 merge/split，保留 relocate、swap、destroy/repair、route reorder、机型、无人机、电池和资源顺序邻域。每个离散候选仍由统一物理模块和精确条件最早开工调度重新计算。
3. Q3 将 23 个运输架次、3 个中继架次声明为搜索目标，不作为硬编码答案。所有入选候选仍必须通过 HiGHS 条件时序优化、硬截止、资源冲突、SOC、DEM LOS、双向预算和 1 s/0.5 s 联合通信采样。
4. 新增 Q3→Q4 前置一致性约束：Q3 多点路线诱导的服务区连通分量不得少于 3，否则无法执行题目要求的 K=3 独立分区。Q3 与 Q4 复用同一 `service_components` 实现，删除重复并查集代码。
5. 生产搜索轨迹改为记录全部改进点和周期检查点；Q3另独立累计每个算子和拒绝原因，避免几十万条重复记录掩盖审计信息。

## 3 个中继架次未采用的原因

对最终 23 架次运输方案进行了候选点集合覆盖检查，空间上存在 3 点覆盖组合；但将组合送入正式联合 LP 后，因中继服务窗口、两架中继无人机复用、能源组件充电和硬截止共同约束而不可行。故正式结果保留 4 个中继架次。该结论只说明当前候选集和搜索预算内未找到 3 架次可行解，不构成全局不可行证明。

## 精确性边界

- 精确：Q1 集合划分；固定 Q2 离散方案的最早可行调度；固定 Q3 离散方案与充电分支的 HiGHS 连续时序；Q4 规范分区穷举。
- 启发式：Q2 分组、路线、机型和资源的外层搜索；Q3 运输/中继离散组合与空间候选搜索。
- 因此 Q2、Q3 均不声称全局最优。固定当前Q2货箱分组、访问顺序和机型时，按各型总任务时长除以实体无人机数量，得到A/B/C型工作量下界36.075/129.136/133.426分钟。当前133.763分钟距该下界只有20.21秒；因此仅精确化资源排序不足以达到116.79分钟，必须改变分组、路线或机型分工。该下界不是原问题的全局下界。复现：`python scripts/diagnose_transport_load.py`。Q3则需要构造同时满足3个中继紧凑窗口的运输分组邻域。
